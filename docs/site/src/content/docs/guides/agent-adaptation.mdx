Preparing an Agent for RL training is straightforward. The
side-by-side below shows a deployed Bedrock AgentCore agent and the
RL-adapted version using `AgentCoreRuntimeApp`.

## Before vs After

<Tabs>
  <TabItem label="Before">

A math agent that uses [Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) and the [Strands Agents](https://strandsagents.com/) framework.


```python
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent
from strands.models import BedrockModel
from strands_tools import calculator

app = BedrockAgentCoreApp()


@app.entrypoint
def invoke_agent(payload):
    model = BedrockModel(model_id="us.anthropic.claude-sonnet-5-5")
    agent = Agent(
        model=model,
        tools=[calculator],
        system_prompt="Solve the math problem step by step.",
    )

    user_input = payload.get("prompt")
    response = agent(user_input)
    # Skip the leading reasoningContent block from adaptive thinking.
    content = response.message.get("content") or []
    return "".join(block["text"] for block in content if "text" in block)


if __name__ == "__main__":
    app.run()
```

  </TabItem>
  <TabItem label="After — adapted for RL">

The tools, system prompt, and agent logic stay the same.


```python
from agentcore_rl_toolkit import AgentCoreRuntimeApp
from strands import Agent
from strands.models.openai import OpenAIModel
from strands_tools import calculator
from reward import MyReward

app = AgentCoreRuntimeApp()
reward_fn = MyReward()


@app.entrypoint
def invoke_agent(payload: dict):
    # Configure the model endpoint at runtime via the invocation payload.
    cfg = payload["_config"]
    model = OpenAIModel(
        client_args={"api_key": cfg.get("api_key") or "EMPTY", "base_url": cfg["base_url"]},
        model_id=cfg["model_id"],
        params=cfg.get("sampling_params", {}),
    )
    agent = Agent(
        model=model,
        tools=[calculator],
        system_prompt="Solve the math problem step by step.",
    )

    response = agent(payload["prompt"])

    # Compute a scalar reward.
    content = response.message.get("content") or []
    reward = reward_fn(
        response_text="".join(block["text"] for block in content if "text" in block),
        ground_truth=payload["answer"],
    )
    return {"reward": float(reward)}


if __name__ == "__main__":
    app.run()
```

## Deploy to AgentCore Runtime

Once the code is adapted, deploy with the
[`bedrock-agentcore-starter-toolkit`](https://github.com/aws/bedrock-agentcore-starter-toolkit)
CLI. A minimal deploy:

```bash
uv tool install bedrock-agentcore-starter-toolkit
agentcore configure \
    --entrypoint rl_app.py \
    --name my_rl_agent \
    --requirements-file pyproject.toml \
    --deployment-type container \
    --non-interactive
agentcore deploy --agent my_rl_agent
```

A successful deploy prints the **agent runtime ARN** — that's the
identifier the training backend uses to invoke the agent. For verl and slime,
configure the HTTP session backend:

```yaml
rollout_session_backend:
  backend: agentcore_rl_toolkit.rollout_session.agentcore_http_session.AgentCoreHttpSession
  agentcore_runtime_arn: "arn:aws:bedrock-agentcore:REGION:ACCOUNT:runtime/AGENT_ID"
```

:::note[Notes]
- **Deployment options are evolving.** AgentCore currently ships two deployment
  paths — the older
  [`bedrock-agentcore-starter-toolkit`](https://github.com/aws/bedrock-agentcore-starter-toolkit)
  (what the examples use; `agentcore configure` / `agentcore deploy`)
  and the newer
  [`aws/agentcore-cli`](https://github.com/aws/agentcore-cli)
  (`agentcore create` / `agentcore deploy`). Flag names and defaults
  differ. Examples in this repo track the starter toolkit today;
  expect this guide to migrate as `aws/agentcore-cli` stabilizes.
- **VPC visibility.** If your inference server (vLLM / SGLang /
  gateway) lives in a private VPC, deploy the agent into the same
  VPC with `agentcore configure ... --vpc --subnets subnet-0abc...
  --security-groups sg-0def...` — otherwise AgentCore's default
  public network route can't reach a private endpoint.
:::

For a worked end-to-end deploy (IAM role, ECR push, first-time AWS
setup), see the
[Strands Math Agent example](/agentcore-rl-toolkit/examples/strands-math-agent/).
For containerized or advanced deploys (custom Dockerfiles, direct
code deployment, non-CLI workflows), see AWS's
[Get started with AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-getting-started.html)
and its
[custom / without-CLI path](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/getting-started-custom.html).
